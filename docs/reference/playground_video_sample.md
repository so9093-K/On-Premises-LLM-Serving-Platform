# Playground 영상 샘플

영상 분석 예제는 직접 제작한 **무음 합성 도형 영상**을 사용한다. 실제 촬영 영상이나 외부 자료가 아니며 사람·음성·사용자 데이터를 포함하지 않는다. 생성 스크립트와 샘플은 저장소의 Apache-2.0 라이선스를 따른다.

## 자산과 제작 조건

| 항목 | 값 |
|---|---|
| 원본 | `assets/demos/inputs/sample-video.webm` |
| UI 번들 입력 | `ui/control-plane/src/playgroundAssets/sample-video.webm` — 원본과 동일한 바이트 |
| 제작일 | 2026-10-21 |
| 형식 | WebM / VP9 / yuv420p, 오디오 트랙 없음 |
| 해상도·길이 | 640×360, 8초, 6 fps, 48프레임 |
| 크기 | 4,226바이트 |
| SHA-256 | `6a7d85435cb8b954fc7e36b71d428a568be9ddff46a30cc4127b33c35ac7b21d` |
| 생성 환경 | PyAV 17.1.0, NumPy 2.2.6, libvpx-vp9 |

WebM/VP9는 검증에 사용하는 기본 Chromium에서도 직접 재생할 수 있다. 샘플은 Vite의 `?no-inline`으로 외부 정적 자산에 고정하여 작은 파일도 기존 same-origin 미디어 CSP를 따른다.

재생 시 빨간 정사각형이 오른쪽으로 이동하고 파란 원이 추가된 뒤, 빨간 정사각형이 아래로 이동한다. 마지막에는 두 도형이 함께 남아 있다. 예제 질문은 처음·중간·마지막에 보이는 도형을 구분하도록 한다. 움직임의 정확한 궤적·시각을 정답으로 보장하지 않는다.

재생성은 위 의존성을 갖춘 별도 도구 환경에서 실행한다. 일반 앱 개발 환경에는 영상 인코더 의존성을 추가하지 않는다.

```bash
python scripts/media/generate_playground_video.py /tmp/sample-video.webm
```

인코더 버전이 달라지면 바이너리 해시가 달라질 수 있다. 자산을 교체할 때 두 복사본, 카탈로그의 크기·길이·해상도, 생성물과 이 기록을 함께 갱신한다.

## UI와 요청 계약

- 영상은 Console의 same-origin 정적 자산으로 로드하며 자동 재생·자동 추론하지 않는다. 재생·일시정지와 펼칠 수 있는 장면 설명을 제공한다.
- 공개 `/v1/models`의 `video` 지원, WebM 허용, 바이트·첨부 개수·길이·프레임 픽셀 제한에 맞을 때 예제를 적용한다. 표시하는 프레임 상한은 모델의 공개 정책이며, 브라우저가 모델의 실제 내부 샘플링 수를 측정한 값이 아니다.
- 등록된 길이·해상도 검사는 이 고정 샘플에 대한 검사다. 임의 업로드 파일의 길이·프레임 수를 브라우저에서 새로 디코딩하는 기능은 포함하지 않는다. Gateway와 Runtime이 최종 입력 허용 여부를 판정한다.
- 입력에 적용한 뒤 사용자가 **보내기**를 누르면 기존 `/v1/chat/completions`로 `video_url`의 WebM data URL과 질문을 전송한다. 장면 설명·정답은 요청에 추가하지 않는다.
- 완료된 요청의 **코드로 사용하기**는 전송한 JSON과 영상 바이트를 보존한다. 예제의 검증 대상은 무음 영상의 시각적 장면 비교다.

## 검증 범위

Node 회귀 테스트는 지원·형식·개수·용량·길이·해상도 경계와 원본 자산 일치, `video_url` 직렬화를 확인한다. Chromium 검증은 Desktop 1440×900과 Mobile 390×844에서 실제 WebM 메타데이터·재생·수동 전송·요청 JSON 내보내기를 확인하며, API 응답은 명시적인 Mock이다.

실제 Runtime 검증은 브라우저 Mock 검증과 구분하여 기록한다. 단일 샘플의 응답 성공은 다른 모델·Target·코덱의 지원이나 분석 정확도를 증명하지 않는다.

### 2026-10-21 실제 Linux/NVIDIA 검증

- `linux-nvidia-dynamic`, RTX 4090, Gemma 4 E4B IT의 공개 `local-main`으로 위 해시의 최종 WebM과 카탈로그 질문을 전송했다. UI의 `buildChatRequest`가 만든 요청을 실제 Gateway에 전송했으며, API 응답을 Mock하지 않았다.
- HTTP 200, SSE `[DONE]`, `finish_reason=stop`, 사용량 2,459 입력·46 출력·2,505 총 토큰을 확인했다.
- 실제 응답은 처음 빨간 정사각형, 이후 파란 원, 마지막 두 도형을 구분했다. 이 단일 응답으로 이동 궤적·정밀 시간 분석 성능을 주장하지 않는다.
- 원시 요약은 로컬 검증 산출물 `reports/validation/playground-video-example.json`에 남긴다. 일반 CI는 실제 GPU 검증을 수행하지 않는다.
