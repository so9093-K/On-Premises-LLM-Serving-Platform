# ADR-0060: 로컬 실행은 Git과 독립적으로 소스를 식별한다

## Status

Accepted.

## Context

ZIP이나 복사한 소스에서도 플랫폼을 실행할 수 있어야 한다. Git은 버전 관리 도구이며
운영에 필요한 소스 파일의 소유권이나 실행 허가를 결정하는 주체가 아니다. Git 설치 누락,
메타데이터 부재, 소유권 검사 실패가 포트 변경을 막아서는 안 된다. 출처 조회 실패를
이유로 임의의 기존 로컬 이미지를 현재 소스와 일치한다고 판단해서도 안 된다.

## Decision

1. 기동·상태·종료와 포트 변경은 Git을 필수 도구로 요구하지 않는다. 전역 Git 설정을
   변경하거나 소유권 검사를 우회하지 않는다. 소스 갱신·커밋·PR은 개발자의 Git 작업이다.
2. 포트 변경은 명시된 소스 영역과 텍스트 확장자로 대상 파일을 선택한다. Git index를
   조회하지 않는다. 숨김 파일·캐시·바이너리·심볼릭 링크는 제외하고 `.env`는 기존의
   역할별 포트·내부 URL 변경 계약을 따른다. ADR-0059의 계획·검증·복구 계약을 유지한다.
3. 공통 출처 조회 모듈은 Docker COPY 입력과 빌드 스크립트의 상대 경로·내용·실행 비트로
   SHA-256 식별자를 계산한다. 로컬 인증값·모델 캐시·Git 정보·배치 경로는 포함하지 않는다.
   Platform·Unified vLLM 빌드와 기동 시 이미지 판정은 같은 계산을 사용한다.
4. Git 출처는 조회에 성공할 때만 커밋·clean/dirty 상태로 기록한다. Git이 없거나 조회가
   실패하면 로컬 소스(`source_state=local`)로 표시한다. Git 커밋 라벨은 빈 값으로
   두어 기반 이미지의 커밋을 플랫폼 커밋으로 승계하지 않으며 내용 해시는 유지한다.
   실패한 `git status`를 clean으로 처리하지 않는다.
5. 로컬 이미지는 `ai_model_serving.source_digest`가 현재 입력과 같아야 재사용한다.
   Git 정보가 있는 경우 기존의 clean 커밋 일치 조건도 적용한다. Git 정보를 모를 때에도
   내용 일치 검증을 생략하지 않는다. 외부 registry digest는 배포자가 지정한 불변 입력이다.

## Consequences

소스 압축본과 Git 소유권 오류 환경에서도 같은 운영 명령을 사용한다. 내용 해시는 로컬
소스 변경 감지 수단이며 서명·배포자의 신원·공식 릴리스 여부를 증명하지 않는다.
해시 라벨이 없는 이전 로컬 이미지는 다음 기동에서 빌드 캐시를 사용해 갱신한다.
소스 변경은 기존과 같이 이미지 재빌드·Runtime 준비 대기를 유발할 수 있다.
파일 권한·잘못된 설정·Docker 접근 실패 등 실제 실행 조건은 여전히 검증한다.

## Validation

회귀 검증은 Git 부재·소유권 거부·status 실패, 압축본의 포트 계획·적용,
소스 변경 감지·secret/캐시 제외·서로 다른 배치 경로의 식별 일치와 구형 이미지의
재빌드 필요 판정을 다룬다. Bash 빌드와 Python 기동의 식별 결과도 비교한다.
